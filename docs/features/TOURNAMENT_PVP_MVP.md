# Турнир / PvP 10+0 — разработка

Статус: этап 1 интеграции реализован в ветке feature/tournament-pvp-mvp-20261022. Main не изменён, ожидается ручная приёмка.

## Продуктовые решения
- Реальные PvP-шахматы, 10 минут каждому без добавления секунд.
- Турнир влияет на общую Мощь Путешествия. Подбор из текущей Мощи; после двух нормальных поражений — мягче.
- Доступ через VK и GitHub Pages; случайный поиск и приватное приглашение по ссылке/коду.
- Скины отрядов — только из купленных на Арене, без игровых преимуществ.
- Если соперника нет, явное предложение играть против ИИ, никогда не подставлять бота тайно.
- Осколки чести и Мощь начислять только после подтверждения результата сервером.

## Этап 1 — выполнено
- Новый пункт Турнир в главном меню, RU/EN.
- Экран 10+0, реальная карусель 14 рас из сохранений Арены, блокировка некупленных.
- Показ текущих Мощи и Осколков чести.
- Входы: случайный поиск, приглашение друга, ввод кода. Ссылка с tournament_room открывает ввод кода.
- Если сервер отсутствует, честное сообщение о недоступности, без выдуманных матчей и наград.
- Отдельная мобильная верстка и браузерные тесты в размерах 390×844 и 768×1024.

## Следующие этапы
2. Отдельный Cloudflare Worker и SQLite-backed Durable Objects, шахматный движок на сервере, часы и reconnect.
3. Приватные комнаты, VK ↔ GitHub Pages.
4. Реальная очередь, подбор по Мощи, смягчение после двух поражений, fallback Arena.
5. Защищённые результаты, баланс Осколков, Мощь; отдельная модель для анонимных игроков Github Pages.
6. Двухклиентные тесты, ручная приёмка, production-релиз.

## Инфраструктура
Cloudflare Worker для PvP отдельный, не перезаписывать leaderboard.
Durable Objects создавать через new_sqlite_classes, с отдельным секретом сессий.
Без серверного учёта нельзя безопасно начислять соревновательную валюту.
