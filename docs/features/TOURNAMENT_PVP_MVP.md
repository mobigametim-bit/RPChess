# Турнир / PvP 10+0 — журнал реализации

Статус: **рабочий staging с настоящим матчем двух игроков**, feature/tournament-pvp-mvp-20261022, draft PR #164. В main не переносить до приёмки экономики и безопасности.

## Продуктовые решения
- Классика 10+0: по 10 минут каждому без инкремента.
- Подбор от Мощи Путешествия; PvP должен менять общую Мощь после подтверждённого результата.
- ВК и прямые игроки GitHub Pages в одной PvP-системе.
- Купленные на Арене расы — косметика; Люди по умолчанию.
- Приглашение по ссылке/коду, случайный поиск; предложение сыграть с ботом только с явным обозначением ИИ.
- PvP-награды в Осколках чести только через сервер, без клиентских самоотчётов.

## Исправление поиска разных уровней Мощи (23.10.2026)
- Исправлена зависшая очередь: теперь каждый опрос `/v1/queue/status` выполняет повторную попытку подобрать пару из уже ожидающих игроков; не нужно ждать появления третьего.
- Стартовый диапазон близости по Мощи — 160, с каждой секундой ожидания расширяется на 125 вплоть до полного диапазона 100–3500. Близкие по Мощи кандидаты по-прежнему имеют приоритет.
- Истёкшие заявки от неактивных клиентов отсекаются через 25 секунд без обновлений; при активном клиенте `seenAt` продлевается статус-поллингом.
- Добавлена настоящая Cloudflare E2E-регрессия для пары 2200 (старый профиль) и 500 (новый профиль инкогнито), с проверкой одинакового `matchId` и серверного snapshot.
- Успешный деплой и тест: https://github.com/mobigametim-bit/RPChess/actions/runs/39867087721
- Доработка не затрагивает `main` и систему начисления наград; остаётся обязательная ручная приёмка.

## Турнир: шах и связки — визуальные эффекты (23.10.2026)

- Турнир использует ту же красную ауру шаха `assets/vfx/aura_red.png`, что и Арена. Класс `classic-square--check` ставится королю стороны под шахом из авторитетного шахматного snapshot; ориентация доски игрока на определение клетки не влияет.
- Турнир использует общий `applyPinIce` из `game/js/king-pin-ice.mjs` (без собственной копии правил). Полная абсолютная связка: `pin_ice_full.png`, частичная: `pin_ice_partial.png`. Прозрачность 50%, анимация появления 160 мс и `prefers-reduced-motion` уже реализованы в общем модуле.
- Серверные polling snapshots каждые 2,4 секунды больше не пересоздают доску и ледяные слои, если FEN и выбранная клетка не изменились. При изменении позиции после хода эффекты пересчитываются на обоих клиентах.
- Расширен существующий двухбраузерный live PvP E2E: последовательность Рюи Лопес (2...Nc6 3.Bb5 d6 4.Bxc6+) проверяет полную связку на c6, красную ауру короля e8 после шаха, удаление ледяной накладки после взятия и стабильность слоя между опросами. Частичная связка дополнительно покрыта существующими тестами общего `king-pin-ice`.
- Только ветка PR #164, без слияния в `main`; ручная приёмка ещё обязательна.

## НЕ готово, нельзя заявлять о релизе
1. Подлинная VK-идентичность: до установки отдельного `VK_APP_SECRET` подключение VK работает как гостевое. Профиль прямого GitHub Pages также гостевой и зависит от токена устройства.
2. Защищённое изменение Мощи Путешествия и Осколков чести после PvP, дедупликация server receipts, антифарм, защита от накрутки матчами друзей. Пока награды и Мощь **не начисляются**.
3. После двух проигрышей подряд подбор должен делать сервер (сейчас интерфейс передаёт нулевую серию, а сервер допускает клиентское поле); серверный рейтинг и отклонение для разных навыков ещё необходимо реализовать.
4. Возврат в незавершённый бой **после полного перезапуска WebView**; снимки партии на сервере уже доступны, но восстановление UI необходимо доработать.
5. Нужны итоговые UX-правки, настоящий контроль VK/GitHub Pages на двух устройствах, нагрузка, антиспам и лимиты пользователей, финальные локализации и ручная приёмка.
6. В текущем staging используется защищённый HTTP-поллинг примерно 2,4 с, пока без WebSockets. Для 10+0 допустимо в прототипе, до массового запуска оценить WebSocket Durable Objects Hibernation.
