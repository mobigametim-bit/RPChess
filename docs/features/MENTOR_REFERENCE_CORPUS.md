## 1. Основа — открытая шахматная база Lichess (CC0)

Официальный источник: https://database.lichess.org/#puzzles  
Официальная документация набора: https://huggingface.co/datasets/Lichess/chess-puzzles  
Использованный компактный срез исходного CSV (первые 500 записей): https://github.com/DSerejo/lichess-puzzle-mixer/blob/master/testdata/lichess_sample.csv  
Лицензия оригинального набора головоломок: **CC0**.

В `tests/fixtures/mentor-reference-puzzles.json` зафиксированы **41 запись** из данного среза: исходный FEN, полная UCI-линия, исходные Lichess-теги, рейтинг задачи, популярность, ссылка на саму задачу и исходную партию. Суммарно **43 разных Lichess-тематических тега**. Это маленький устойчивый corpus для regression, не претензия на репрезентативную выборку из миллионов задач.

**Критически важная семантика записи:** `fenBeforeSetup` — позиция **до** подготовительного хода оппонента; `line[0]` — этот подготовительный ход; **решение задачи начинается с `line[1]`**. После первого хода реальная позиция решателя — `afterSetupFen`, вычисляемая через `ClassicChessEngine`. Без этой нормализации нельзя сравнивать видимую доску, пол игрока и первый ход тактического решения. Теги и опубликованная линия принадлежат Lichess; сами по себе не подтверждают, что именно наша версия Stockfish 18 Lite оценит подготовительный ход как ?!/?/??.

## 4. Что уже проверяется в существующей регрессии

В `tests/mentor-training-feedback.cjs` (без создания нового suite):

1. Каждая исходная FEN читается нашим `ClassicChessEngine`; подготовительный ход и **вся** опубликованная последовательность решения должны быть легальными.
2. После setup хода сторона меняется; пользовательской позицией считается именно новая FEN.
3. `tacticalEvidence` должен воспроизвести точно ту же легальную линию без несуществующих полуходов; выбранная учебная фигура находится на доске **после** setup.
4. Тематический охват, идентификаторы, реальные ссылки и основные поля пяти полноценных партий проверяются на целостность.

**Чего эти проверки НЕ доказывают:** отсутствие false positive в наших 18 эвристиках, корректность SEE, точность классификации ошибок на мобильном Stockfish, стратегическую адекватность свободного текста LLM и вынужденность комбинаций. Для такого доказательства нужны набор **положительных/отрицательных утверждений для каждой позиции**, анализ альтернативных защит и отдельная проверка достаточной глубины. Не помечать эти пункты как PASS до следующих этапов.

## 5. Что обнаружено в аудите текущего PR #187

- Локальная быстрая оценка: до и после хода, по **260 мс**; при ошибке — дополнительный поиск до **1700 мс** с ограничением PV до **20 полуходов**. Движок `Stockfish 18 Lite` из `finished-game-review.mjs` / `ChessAIAdapter`.
- MultiPV = 2 уже поддерживается, но **нет** систематического доказательства угрозы с анализом альтернативных ответов; события извлекаются из **одной** главной линии.
- Текущее поведение в ветке останавливает соперника на всех `inaccuracy/mistake/blunder` и может просить выбрать фигуру из первого легального ответа даже при `positional`. Это **не соответствует** утверждённому продуктовым решением B правилу: без доказанной непосредственной угрозы — короткий комментарий **без паузы**.
- Детектор учитывает геометрию атак и отдельных защитников, но **полноценного SEE ещё нет**.
- API для свободного текста LLM всё ещё может использовать предыдущую версию серверного промпта; новая структура педагогических фактов не развёрнута на изолированном API.
- Автотест с Lichess набором нужен как **начальная реперная точка**, а не как обещание корректности всех идей.

## 6. Следующие шаги

1. **Контрольная точка А, этап 2:** определить стабильный критерий ухудшения шансов победы, не меняя общую оценку в Tournament/Arena без отдельной проверки.
2. **Этап 3:** реализовать SEE и тестировать на этих реальных позициях вместе с искусственными контрпримерами защищённости/невозможных взятий.
3. **Этап 4:** классифицировать `verified_immediate_tactic` и `unverified_or_positional`, подключить MultiPV/защиты. При втором исходе партия продолжает идти — никаких ложных тактических заданий.
4. Лишь после этого — «найти угрозу → необязательно исправить собственный ход → объяснение LLM» и адаптивная производительность, по плану.

**Осторожно с источниками:** коллекции Arasan20/WAC/STS/прочих EPD могут быть полезны как дополнительные тестовые наборы движка, но права на их конкретные файлы требуют отдельной проверки. Непроверенные EPD и чужие аннотации не копируем в репозиторий.
