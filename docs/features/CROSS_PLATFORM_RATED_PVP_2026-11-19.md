# Рейтинговый Турнир — единый RPChess ID для VK, OK и Web (19.11.2026)

## Решение владельца
Игровые правила, Elo, Осколки чести, Турнир и глобальный TOP-10 не зависят от площадки запуска. **Не объединять** VK/OK/Web-профили и не переносить между ними сохранения автоматически. Игрок не вводит логин, пароль или код внутри игры.

## Границы доверия и идентификация

- **VK:** как раньше, обязательная проверка свежих подписанных `vk_*` параметров сервером через `VK_APP_SECRET`. Старый VK-профиль и импорт старой статистики сохраняются.
- **OK:** официальные VK Mini Apps параметры с `vk_client=ok` и отдельным идентификатором приложения OK. Сервер сверяет HMAC всех `vk_*` полей с тем же защищённым секретом приложения, timestamp, идентификатор пользователя и отличающийся от VK ID приложения. `vk_client` — только указатель маршрута, не удостоверение личности. Опционально задаётся `OK_APP_ID` для дополнительной проверки конкретного ID после привязки площадки. `VKWebAppGetLaunchParams` не поддерживается OK: параметры берутся из начального URL, без угадывания личности.
- **Web:** случайный RPChess ID + секретный bearer-токен в локальном хранилище браузера; новый Web-профиль возникает только при первом посещении, не автоматически привязывается к социальной личности.
- **База:** существующая `rpchess_profile_v1` (CHECK provider IN web/vk) **не перестраивается**. ОК использует новую независимую таблицу `rpchess_profile_platform_v1` (OK user ID → RPChess UUID). Профиль хранится как внутренний `web`, API для подтверждённого OK-пользователя возвращает `provider=ok`. Никакой перенос/слияние Web или VK записей не выполняется. Браузерные пространства имён `rpchess.profile.auth.ok.v1` и `rpchess.profile.v1.ok.<uuid>` независимы от VK/Web.

## Турнир

- Только **аутентифицированный сервером** RPChess ID (проверенный bearer через Profile Worker) может играть в рейтинговом публичном поиске, независимо от `provider` (vk/ok/web).
- Обычный клиентский `profileId` и произвольные параметры в URL не дают рейтингового статуса. Публичные гостевые сессии без Profile Worker остаются товарищескими. Исторические проверенные VK-сессии продолжают работать.
- Условия рейтинга, Elo K=32, лимит одной пары **два рейтинговых матча за 24 часа**, серверная идемпотентность, частные приглашения/Игра с тенью и `+Elo → +Осколки чести` не изменяются.
- **Ограничение Web:** Web bearer-токен доказывает владение конкретным браузерным профилем, но не уникальность физического человека. Пользователь может создать несколько Web-профилей, очистив хранилище/сменив браузер. Против мультиаккаунтинга нужны отдельные антифрод-правила; это не исправляется определением платформы. Не позиционировать это как подтверждённую личность человека.

## Защита действующей production и выпуск

1. В отдельной ветке прогнать `test:profile`, `test:cloud`, локальные Tournament Durable Objects и PR Focused Checks. Никаких реальных начислений, новых профилей или API-операций на production в CI.
2. **Перед деплоем нового Profile Worker** применить **только additive** `profile-worker/schema.sql` на существующей D1, не удаляя таблицы и профили. Убедиться, что `rpchess_profile_platform_v1` создана.
3. Обновить существующий `rpchess-profile-preview` с прежними секретами и D1. Затем обновить **канонический** `rpchess-tournament-profile-preview` с прежними Durable Objects и `PVP_SESSION_SECRET`. Не использовать legacy Tournament Worker `tournament-worker/wrangler.toml` и не создавать новую DO namespace.
4. После проверки серверов выпустить клиент. Проверить VK, OK и Web с тремя независимыми RPChess ID, повторным запуском OK и Web, матчами VK↔OK и OK↔Web, начислением +Elo/+осколков, нулевым списанием при поражении, запретом рейтинга для анонимного Tournament-гостя и для приглашений.
5. Реальная подпись ОК и производственная авторизация должны быть подтверждены живым запуском из OK, когда он подключён в dev.vk.com. Синтетические тесты не заменяют эту приёмку.
