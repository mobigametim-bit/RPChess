# RPChess — полная тематика шахматных задач Lichess

## Обновление 18.10.2026 — каталог 30 000 подключён в приёмочной ветке

В PR #160 сформирован офлайн-каталог **30 000 уникальных проверенных задач**: 11 498 неизменённых прежних + 18 502 дополнительных из Lichess CC0. Новые задачи находятся в 12 модулях `game/js/puzzles/extra-star-01.mjs` … `extra-star-12.mjs` и подгружаются по выбранному уровню сложности через `puzzle-catalog-loader.mjs`. Строгие квоты по звёздам и целям подтверждаются `tests/puzzle-expansion.cjs`; сводный отчёт — `game/js/puzzles/catalog-data/puzzle-expansion-report.json`.

Проверенные цели: мат в 1/2/3/4/5+, выигрыш материала и поиск лучшего продолжения; тематика — 73 Lichess-тега. Прежняя история решения, награды и сохранения сохраняются. Исправлена гонка CSS компактного экрана при асинхронном импорте новых блоков и сохранение ID задач из разных звёзд в истории no-repeat.

**Границы:** это расширение ровно до 30 тысяч, а не импорт всех 6,15 млн. Web/CI и ручная проверка ветки обязательны до слияния в `main`. Исторические разделы ниже описывают порядок поэтапной разработки на 17.10.2026.


## Решение и масштаб (17.10.2026)

Задача: использовать все тематические категории Lichess, не превращая HTML5-игру в многогигабайтный пакет.

Источники:
- https://database.lichess.org/#puzzles — 6 157 341 задач на 05.10.2026, CSV сжат Zstandard, лицензия CC0.
- https://lichess.org/training/themes
- https://github.com/lichess-org/lila/blob/master/translation/source/puzzleTheme.xml — официальный словарь тем.
- Действующий каталог RPChess: `game/js/puzzles/catalog-data/puzzle-catalog-11498.json.gz` — 11 498 задач, исходная выборка 50 000 из снимка 2022 года.

Сентябрьский архив 6,1 млн задач оценивался примерно в 304 МБ (сжатый `.csv.zst`). Для нынешнего файла ориентир ~300–320 МБ; реальный Content-Length октябрьского файла нужно подтвердить при загрузке. Обычный CSV при распаковке — существенно больше, приблизительно 1,5–2 ГБ (оценка). Эти числа относятся к полному исходному датасету разработчика, **не** к загрузке игроком.

## Реализовано — этап A: поддержка словаря тем (PR #160)

- В `game/js/puzzles/puzzle-theme-catalog.mjs` зарегистрированы 73 тематических тега из официальной номенклатуры (с дополнительным `enPassant`) с названиями на RU/EN и группами: `tactic`, `special`, `mate`, `endgame`, `phase`, `goal`, `length`, `origin`.
- Теги **не взаимоисключающие**. Список `puzzle.themes` берётся только из исходного Lichess CSV. Не выводим новые теги догадками о расположении фигур.
- При показе задачи отмечаем один наиболее содержательный тег (приём/специальный ход/матовая комбинация, затем эндшпиль или фаза партии) рядом с заголовком. Основная цель и алгоритм проверки прежние.
- Работает с имеющимися 11 498 задачами; новая загрузка миллионной базы пока **не произведена**.
- Не менялись матовые критерии, награды, число попыток, Power-сложность, сохранение или no-repeat.

## Этап B — новые цели и строгая нормализация (код подготовлен)

**Формальная цель задачи** отделена от **тематических тегов**. Движок принимает `mate4`, `mate5Plus`, `bestLine` наряду со старыми типами, показывает локализованные RU/EN задачи и применяет ту же проверку UCI-последовательности, ответов соперника и выплат.

В `scripts/import-lichess-puzzles.cjs` добавлены *опциональные*, не меняющие старый импорт функции `typeFromThemesExtended`, `preclassifyExtendedLichessRow` и `normalizeExtendedLichessRow`. Они сохраняют текущие фильтры качества, проверяют легальность линий движком, для длинного мата подтверждают статус `checkmate`, а для `bestLine` исключают ошибочно размеченные матовые комбинации. В старом 11 498-позиционном каталоге новых записей пока нет.

Для расширенной базы предусмотрены цели:
1. `mate4`, `mate5Plus` — проверить фактический мат, легальность всей линии, корректный конец.
2. `bestLine` — «Найдите лучшее продолжение» для `advantage`, `crushing`, `equality`, `defensiveMove`, `quietMove` и других задач без обязательного мата или выигрыша конкретной фигуры. Сверять каждый ход игрока с подтверждённой Lichess source solution и автоматически проигрывать реплики оппонента. Не выдавать успешное решение, не пройдя всю линию.
3. Специальные темы (`promotion`, `underPromotion`, `enPassant`, `castling`) и мотивы (`fork`, `pin`, `skewer`, `sacrifice`, `zugzwang` и другие) описывают тип приёма, а не отменяют формальную цель.
4. Отдельные группы «Дебют», «Миттельшпиль», «Эндшпиль» и подтипы эндшпилей — это фильтры, а не задача «найдите ход, называемый эндшпилем».
5. Не считать каждый тег гарантированным доказательством тактического исхода. Фильтрация и строгая проверка source solution обязательны.

## План — этап C: потоковый импорт и поставка клиенту

- Скачать исходный `lichess_db_puzzle.csv.zst` на **CI/машине разработчика**, а не в игровой браузер.
- Распаковывать потоково (например, `zstd -dc | node ...`), читать CSV построчно, не удерживать 6,1 млн записей в RAM.
- Сначала формировать каноническую позицию: применить первый UCI-ход из `Moves`, затем проверить легальность продолжения и достоверность метки `mate` / `bestLine`.
- Оставить фильтры качества `Popularity>=80`, `RatingDeviation<=100`; добавить исключение дубликатов и невозможных FEN; распределить по 12 уровням рейтинга. Фильтры могут уменьшить реальное количество пригодных задач по сравнению с 6 млн.
- Дополнительно сохранять `OpeningTags` из исходного CSV как отдельные метаданные дебютов (сейчас эти теги отсутствуют в компактном каталоге 11 498). Дебютные названия — не формальные цели шахматного решения.
- Формировать небольшие gzip/brotli чанки по сложности и тематическим группам с индексом, content hash, версией каталога и инвариантами количества; старый каталог оставить fallback.
- **Начальный HTML5-бандл не должен включать все миллионы.** Для прогресса и доступности без сети предусмотреть небольшой встроенный пул; остальное подгружать по HTTP по востребованным категориям/уровням из статического CDN (Cloudflare Pages/R2 или аналог). Не требовать Worker/DB только ради чтения статических задач.
- Подбор задачи детерминированный по `runId`, `routeId`, сложности, фильтру тематик и seed каталога; `puzzleHistory` и resume обязаны сохранять стабильный `puzzleId` между обновлениями. Гарантия no-repeat ограничена доступным пулом/чанками.
- В браузере кешировать небольшие скачанные блоки, не загружать лишнее на слабых мобильных устройствах или внутри VK Mini App.
- Переводы названий на RU/EN и компактные горизонтальные viewport тесты — часть приёмки.

## Приёмка этапов B–C

- Детерминированные unit/regression проверки на synthetic mate4/mate5Plus/bestLine: успешное решение, ошибка, 3 попытки, перезагрузка посередине линии и idempotent выдача награды.
- Full-source streaming validation на стороне CI; отдельные выборочные браузерные проверки нескольких тем и обоих языков.
- Проверить время первой загрузки, объём начальных ресурсов, RAM в мобильном landscape 844x390, работу без сети с fallback.
- Принятие пользователем в preview PR #160, **только потом** merge в main.

**Граница текущего результата:** этап A реализован; в B добавлены движковые типы и нормализатор, а входящая база и браузерное подтверждение новых типов ещё не подключены; C (массовая потоковая поставка) только запланирован. Пользователь не должен получать ложную информацию о том, что все 6,1 млн задач уже доступны в игре.
