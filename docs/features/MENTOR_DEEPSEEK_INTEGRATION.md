# Наставник — интеграция DeepSeek через Gonka

Ветка: feature/mentor-training-mvp-20261107 (PR #186). Main не трогать до ручной приёмки.

## Архитектура

- Шахматную классификацию ?! / ? / ?? определяет **только** сильный локальный Stockfish.
- В запросе API используются FEN до/после хода, UCI сыгранного хода, Stockfish cp/depth, проверенная первая линия ответа соперника.
- Общий mentor-training-feedback-core.mjs повторно воспроизводит ход и варианты через ClassicChessEngine. Не принимает нелегальные ходы, несогласованные FEN, ложную категорию или невалидные PV.
- Строго допустимые факты для модели: немедленное взятие, немедленный шах, немедленный мат, либо только ухудшение оценки. Не сочинять вилки, связки или будущие потери материалов.
- Модель не получает лучший ход из исходной позиции; не должна раскрывать готовое решение игроку. Даже если модель ответит некорректно, есть локальный fallback.
- Запрос асинхронный: ответ соперника и Навигация Назад/Вперёд не ждут DeepSeek. При возврате, смене линии или выходе старые ответы отменяются и не вставляются в новую позицию.
- Позиции и объяснения кэшируются по FEN/ходу/категории/языку; повторный просмотр истории не расходует токены. RU/EN.
- Отдельный Cloudflare Worker **rpchess-mentor-api-preview**, без доступа к другим Workers, VK, профилю, Турниру и D1.
- Браузер получает только короткое объяснение, никакого API-ключа.

## Точное подключение Gonka

Сервис gonka-api.org — сторонний брокер. Документированная базовая точка: https://hskyauefqcgbvgvxkluj.supabase.co/functions/v1/gonka ; POST /chat/completions. Если пользовательский кабинет показывает другой адрес, укажи GONKA_BASE_URL как переменную окружения Worker (с поддержкой только доменов этого брокера).

Имя модели подлежит подтверждению в кабинете пользователя /models, по умолчанию deepseek-ai/DeepSeek-V4-Flash-0731; в этой версии модель закреплена в коде: `deepseek-ai/DeepSeek-V4-Flash-0731`; переменная GONKA_MODEL намеренно игнорируется.

Секрет **GONKA_API_KEY**:
1. Cloudflare Dashboard → Workers & Pages → rpchess-mentor-api-preview → Settings → Variables and Secrets → Add → Secret.
2. Name: GONKA_API_KEY; Value: личный ключ Gonka. НИКОГДА не отправлять ключ в чат, GitHub, frontend, скриншоты или публичные логи.
3. Альтернатива: добавить секрет GONKA_API_KEY в GitHub Actions Secrets (repository scope); изолированный CI использует его только для команды wrangler secret put. GitHub Workflow logs не содержат значения.
4. Установить небольшой лимит бюджета/кредитов в самом кабинете Gonka перед публичным тестом. Cloudflare per-PoP rate bindings приблизительные, НЕ гарантируют глобальный расход.

Работа без секрета: /health возвращает configured:false, POST /v1/explain → 503, игра спокойно отображает безопасное локальное объяснение.

## Безопасность и ограничения

- Только POST /v1/explain, JSON ≤ 4 KB, строгая проверка FEN/ходов/классификации, CORS разрешённых игровых хостов.
- Cloudflare rate bindings: глобально до ~20/мин на PoP, ~5/мин на посетителя на PoP; неполная защита от распределённых запросов/смены анонимного ID. Перед public main нужна более строгая авторизация/лимит бюджета на стороне Gonka.
- Проверенные таймауты моделей: 15 / 18 / 20 секунд; max_tokens 1000 / 900 / 1200 соответственно, без streaming. Максимум три последовательные попытки на одной и той же проверенной позиции.
- Не использовать неконтролируемый origin/proxy URL, не принимать пользовательские system prompts.
- Ошибки API, модель недоступна, неверный JSON → локальное объяснение без нарушений игрового процесса.
- DeepSeek — независимая генеративная модель, факты в свободном тексте невозможно формально доказать на 100%. Верифицируем только легальные данные движка и тип факта; точность фраз требует ручной приёмки.

## Приёмка

## Итерация: углублённый анализ выявленной ошибки

- Быстрая оценка **до и после** каждого хода: как прежде, Stockfish без ограничения силы, по **260 мс** на позицию. Классификация ошибки по прежним порогам не меняется.
- Только если обнаружена ошибка `?!`, `?`, `??`: отдельная задача Stockfish с бюджетом **1700 мс** для позиции **после** ошибочного хода. Соперник на независимом ChessAIAdapter может отвечать без ожидания DeepSeek. Анализ не гарантирует конкретную глубину; движок работает через `go movetime`, max на уровне StockfishReviewEngine — 2200 мс.
- Берём **до 20 легальных полуходов** из глубокой principal variation (PV), а не фиксируем их число; более короткая линия допустима, если Stockfish не нашёл двадцать ходов. При ошибке углублённого анализа остаётся прежнее короткое объяснение.
- Перед отправкой на API сервер заново воспроизводит всю полученную линию через ClassicChessEngine от FEN, проверяет категорию ошибки на **исходных быстрых оценках** и отклоняет нелегальные окончания.
- Вспомогательный аналитический модуль извлекает только факты, наблюдаемые в replay: последовательность с матом против игрока, чистая потеря материала в линии, новое двойное нападение на ценные фигуры, новая абсолютная связка к королю и прямой шах. Описание отвечает, что это **один вычисленный вариант**, а не доказанно форсированный исход против любой защиты.
- В модель передаются **FEN, сделанный игроком UCI, категория ошибки, подтверждённые тактические события (с относительным номером полухода) и до 20 полуходов PV**. Правильный альтернативный ход игрока перед ошибкой **не передаётся**.
- При переходе в другую линию/отмене партии поздние объяснения не появляются на чужой позиции. Запросы ограничены Worker Rate Limit; один разрешённый запрос может вызвать до трёх моделей. Тесты в `tests/mentor-training-feedback.cjs`.

**Граница качества:** проверяем конкретные тактические факты при воспроизведении PV, но не доказываем, что все варианты защиты ведут к той же тактике. Если достоверного мотива нет, ИИ должен сообщать об общем ухудшении без фантазий.

## Тексты наставника и просмотр линии (2026-11-07)

- После быстрой классификации ошибки показывается одна из **20 коротких промежуточных фраз** (RU/EN), пока не завершены глубокий поиск и запрос DeepSeek. Выбор детерминирован для позиции и хода, фразы не выдают решения.
- Если API не ответил, вернул ошибку или неприемлемый текст, вместо ожидания выдаётся короткая типовая заглушка для **неточности / ошибки / зевка** (RU/EN).
- Для хорошего `!` и отличного `!!` переиспользуется существующий `classifyStrongMove` из послематчевого анализа (MultiPV сравнение, глубина, цена альтернативы). Просто «best move» не считается автоматически блистательным. **10 реплик для каждой категории** RU/EN, без DeepSeek.
- Если углублённая линия Stockfish есть, ниже комментария появляется **«Посмотреть»**. Расчёт открывается в боковой панели как кликабельные SAN-ходы (до 20 полуходов), каждый воспроизводится на центральной доске. Нажатия на этот вариант **не меняют историю живой партии**, её курсор, оценку и награды; кнопка «К партии» возвращает доску.
- В задании DeepSeek вместо расплывчатого «В рассчитанной линии» используется конкретный формат: **«Через два хода соперник может создать вилку на ферзя и ладью. Найди, как это предотвратить.»** Количество ходов и цели берутся из перепроверенных событий при воспроизведении PV.
- **Оговорка:** одна PV — не форсированное доказательство при всех защитах. Пишем «может»; при отсутствии подтверждения конкретной тактики — только об ухудшении оценки. Запрещённые расплывчатые ответы отсекаются и заменяются фактологическим локальным текстом.
- Глубина: по-прежнему базовые 260 мс и дополнительные 1700 мс только после ошибки; DeepSeek получает до 20 полуходов. Модель **зафиксирована**: `deepseek-ai/DeepSeek-V4-Flash-0731` без произвольного override.

## Удлинённые объяснения и переключение моделей (2026-11-07)

- Системный запрос требует **2–5 предложений, максимум 500 символов** RU/EN. Проверка на сервере и в браузере теперь допускает до 500. max_tokens увеличен по результатам замеров до 1000 для DeepSeek, 900 для MiniMax и 1200 для GLM.
- Брокер Gonka API уже настроен на https://hskyauefqcgbvgvxkluj.supabase.co/functions/v1/gonka, маршрут POST /chat/completions. Не добавлять /v1 повторно. Ключ остаётся секретом Worker.
- **Последовательная цепочка:** deepseek-ai/DeepSeek-V4-Flash-0731 → MiniMaxAI/MiniMax-M2.7 → zai-org/GLM-5.3-Flash. После успеха остальные не вызываются.
- Бюджет ожидания моделей: 15 / 18 / 20 секунд; клиент ждёт максимум 60 сек после анализа Stockfish.
- Фолбэк на 429, 5xx, timeout, network, invalid JSON/response. На 401/402/403 не повторяем: это общий ключ либо баланс.
- Если все модели не дали ответа, сервер возвращает 503 с обезличенными кодами причин. Секрет, сырые ответы и промпты не пишутся в журнал.
- Браузер выводит локальную заглушку с кнопкой «Повторить запрос ИИ». Неуспех не кэшируется; повторный запрос без переигрывания хода. Успешный ответ кэшируется.
- Источник и причина сохраняются в записи хода: mentorSource, mentorModel, mentorReason, mentorAttempts. Клиент проверяет источник и размер ответа.
- Один входящий запрос может последовательно вызвать до трёх платных моделей, при этом Cloudflare Rate Limit применяется к входящему запросу лишь один раз. Требуется дополнительный бюджетный лимит Gonka.
- Только ветка PR #186, без изменений main.

Проверка перед приёмкой: one-time real Gonka smoke подтверждает модель, HTTP статус и длину ответа; платные обращения запускаются только для отмеченного коммита.

После успешного переключения ответ содержит failsafe-поле failures с моделью и обезличенным кодом сбоя каждой предшествующей попытки. Клиент сохраняет mentorFailures в истории хода для диагностики, без исходных HTTP-тел и ключа.

Три серии реального измерения стабильности (162 прямых вызова) и обоснование по JSON Schema, reasoning_effort и токенам находятся в docs/features/MENTOR_MODEL_RELIABILITY_BENCHMARK.md. Обобщать результаты за пределами тестовой позиции без проверки нельзя.


## Повторы одной модели (2026-11-07)

Для каждого объяснения последовательность зафиксирована: `DeepSeek V4 Flash` → `MiniMax M2.7` → `GLM 5.3 Flash`. **Внутри каждой модели — одна первичная попытка и до трёх повторов (максимум 4).** Только после четырёх неудач переключаемся к следующей. При первом корректном проверенном ответе немедленно прекращаем попытки, не тратим токены дальше.

Повторяем после таймаута, сетевой ошибки, HTTP 429/5xx, невалидного/оборванного JSON, слишком длинного текста и отклонённого шахматным фильтром объяснения. Ошибки авторизации и средств (401/402/403) останавливают цепочку без бесполезных повторов. Между тремя повторами одной модели: 250, 500 и 1000 мс.

Всё выполняет только серверный Cloudflare Worker. Rate Limit проверяет входящий запрос перед платными попытками; **один входящий запрос потенциально создаёт до 12 исходящих платных обращений** — это важно для расходов, а Rate Limit не является жёстким бюджетным ограничением Gonka. При отказе последней модели остаётся локальная заглушка и ручное повторение без изменения партии.

Сохраняем `attempts` (общее число запросов), `modelAttempt` (номер попытки успешной модели) и `failures` (модель, номер попытки, безопасный код причины). Промпты, ключи, тексты ошибок провайдера не логируются.

При таймаутах 15/18/20 секунд на DeepSeek/MiniMax/GLM худшее ожидание может превысить **3,5 минуты**: 4 × (15 + 18 + 20) = 212 секунд плюс задержки и сеть. Поэтому клиентский предел увеличен до 230 секунд. Партия во время ожидания продолжает работать. До ручного подтверждения пользователя релиз остаётся только в feature-ветке.
