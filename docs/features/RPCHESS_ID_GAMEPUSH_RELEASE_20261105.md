# RPChess — выпуск RPChess ID, D1, GamePush для VK и общего ТОП-10

Дата подготовки: 2026-11-05. Это контрольный **release candidate**, а не автоматическая публикация действующего приложения.

## Что включается в канонической сборке

- Для URL `https://mobigametim-bit.github.io/RPChess/` без специальных query-флагов включён RPChess ID / Cloudflare D1. Так работают VK iframe, браузерная Web-версия и устанавливаемая PWA на этом же origin. Яндекс и сторонние домены на этом этапе не переводятся.
- При подтверждённом формально корректном VK launch (`vk_app_id=54754579`, непустой `sign`, числовой `vk_user_id`) на каноническом сайте включается GamePush SDK (проект 31247). Для обычного Web не включается.
- Реклама из GamePush доступна при успешной авторизации SDK; при терминальном сбое SDK в **доверенном VK iframe** используется существующий VK Bridge. Одна попытка показа не вызывает обе системы одновременно. Всплывающее закрытие/отмена не выдаёт наград.
- Общий TOP-10 «Великие полководцы», собственное место и новый Турнир используют RPChess ID и D1. Старые таблицы `leaderboard_v1` и сохранения `rpchess_v1_cloud_*` **не изменяются**.
- VK Stories по-прежнему вызываются через VK Bridge, в том числе если GamePush используется для рекламы. Игровая Мощь и PvP Elo остаются разными показателями.
- Используемые сервисы пока носят имена `rpchess-profile-preview` и `rpchess-tournament-profile-preview`. Они опубликованы на Cloudflare, реально читают D1 и привязывают RPChess ID, но **не должны подвергаться экспериментальным несовместимым деплоям после production rollout**. Перед отдельной инфраструктурной миграцией нужны стабильные именованные Workers с перенесёнными секретами и непрерывностью данных.

## Музыкальная лицензия

## Безопасный откат

Уже опубликованная каноническая игра изменится **только после ручного GitHub Actions deploy**. Обычный merge в `main` запускает валидацию, но не выкладывает Pages.

- `?rpchess_profile=0&rpchess_gamepush=0` — временный диагностический запуск старой локальной/VK Cloud системы **без удаления старых данных** и рекламы через VK Bridge.
- `?rpchess_gamepush=0` — RPChess ID остаётся на D1, но реклама переключается обратно на проверенный нативный VK Bridge.
- Запуск `?rpchess_profile=1&rpchess_gamepush=1` остаётся доступен для изолированных GamePush-стендов.
- Старые незавершённые VK Путешествия намеренно не переносятся в новую систему профиля; завершённая статистика и Arena восстанавливаются однократно. Старые Cloud VK-записи не удаляются.
- Web/PWA: аккаунт создаётся без внешней регистрации, но при потере локального секретного токена самовосстановление недоступно. Старые непривязанные локальные Web-сохранения не импортируются автоматически, чтобы не смешивать Web с VK аккаунтом на одном origin; старые данные сохраняются и доступны через rollback URL.

## Внешнее действие перед опубликованием

В GamePush → Доверенные сайты разрешить `https://mobigametim-bit.github.io` для реальной VK-версии. На предыдущем скриншоте этот сайт был **выключен**, тогда как Cloudflare Preview был разрешён и отмечен «Тестовый». Для production не требуется включать статус тестового сайта. Не менять секретный ключ, не раскрывать токены и signed VK launch.

## Автоматическая и ручная приёмка

1. CI на **точном коммите релизной ветки**: `npm run gate:local`, Playwright браузерные сцены, проверка явных rollback-флагов, лицензия и VK story capability; после сборки файл `dist/music/epic_music3.mp3` отсутствует, и в музыкальном каталоге его нет.
2. После merge в main — отдельный канонический gate, **без** публикации VK/Pages. 
3. Вручную в VK (ПК + Android) после разрешения production origin: GamePush diagnostics `ready`, `ads.backend=gamepush`, Rewarded ×2 строго один раз и отмена без бонуса, Fullscreen, VK Story, D1 Power/Chronicle/Arena, TOP-10, Турнир Web/VK. Проверить офлайн/новый запуск и другие аккаунты.
4. Только после подтверждения владельца сделать `workflow_dispatch` **Deploy RPChess to GitHub Pages** из main. Убедиться, что все устройства получают новый релиз и у владельца остался старый Cloud fallback.
