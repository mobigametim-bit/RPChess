# 05 — Skirmish

## Назначение
Skirmish — главный оригинальный режим RPChess и слой подготовки непосредственно перед боем. Roster отвечает на вопрос **кто принадлежит текущему забегу**, а Skirmish — **какие здоровые персонализированные фигуры участвуют именно в этой встрече**.

## Утверждённый UX
- экран встречи показывает название, звёздную сложность и приблизительную силу противника;
- точный состав врага и точное Elo до старта боя не показываются;
- персонализированный King выбран автоматически, стоит 0 и не может быть удалён;
- одновременно можно взять максимум 16 фигур вместе с King;
- общий лимит — 39 командных очков;
- здоровые фигуры можно добавлять/убирать кликом;
- wounded/dead остаются видимыми, но недоступны для выбора;
- счётчики `Фигуры / 16` и `Командование / 39` постоянно видимы;
- неправильный выбор блокируется сразу с понятной причиной;
- выбранный боевой состав отображается отдельно от каталога доступных фигур;
- перед боем показывается компактный неинтерактивный preview автоматической расстановки;
- ручной drag-and-drop расстановки и отдельного confirmation-screen нет;
- `Начать стычку` сразу создаёт стартовую позицию и открывает существующую шахматную доску;
- минимального состава кроме обязательного King нет.

## Классическая стоимость
- Pawn — 1;
- Knight — 3;
- Bishop — 3;
- Rook — 5;
- Queen — 9;
- King — 0.

## Автоматическая расстановка v1
- сторона игрока занимает 1–2 горизонтали;
- сторона противника занимает 7–8 горизонтали;
- одинаковый состав + одинаковый encounter seed дают одинаковую стартовую позицию;
- на каждой стороне ровно один King;
- после старта действуют только классические шахматные правила;
- Skirmish не создаёт второй chess engine и использует существующий `ClassicChessEngine` через FEN.

## Adaptive enemy v1
Сложность встречи фиксируется до выбора состава игрока. До боя показываются только тип встречи, звёзды и приблизительный диапазон силы.

Точная армия противника генерируется один раз при `Начать стычку` из:
- encounter difficulty;
- финальных очков/размера армии игрока;
- encounter seed.

Противник не обязан зеркально повторять состав игрока. Сила Stockfish задаётся tier встречи; техническое Elo не является pre-battle информацией.

## Последствия партии
- взятая персонализированная не-King фигура получает `wounded` / `ТЯЖЕЛО РАНЕН`;
- взятые именные фигуры отслеживаются Skirmish-слоем поверх классического движка;
- ничья не убивает King, но все взятые именные не-King фигуры всё равно остаются wounded;
- **мат игроку = смерть персонализированного King = конец забега**;
- мат противнику = победа Skirmish;
- King не переводится в wounded после мата: он сразу получает `dead`, а run получает `ended=true` и `endReason=king_dead`.

## Feedback во время боя
Взятие именной фигуры не останавливает игру модальным окном. Показывается короткий non-blocking toast вида `Имя — ТЯЖЕЛО РАНЕН`.

## Aftermath
После окончания партии открывается отдельный экран итогов:
- `ПОБЕДА`, `ПОРАЖЕНИЕ` или `НИЧЬЯ`;
- список выживших;
- список тяжело раненых;
- список погибших;
- при смерти King явно сообщается, что run завершён.

Gold/XP и другие будущие награды здесь пока не выдумываются до реализации Resources/reward systems.

## Persistence
Run schema остаётся совместимой с `rpchess.reboot.v1.run` и получает дополнительные поля:
- `ended`;
- `endReason`;
- `skirmishCount`;
- `lastSkirmish`.

Старые Roster save автоматически гидратируются значениями по умолчанию (`ended=false`, `skirmishCount=0`). Ended run остаётся сохранённым как история, но кнопка `Продолжить` становится недоступна.

## Mobile
- информация о встрече сверху;
- выбранный боевой состав идёт перед каталогом доступных бойцов;
- нижняя action bar остаётся sticky и показывает `pieces / 16`, `points / 39`, `Начать стычку`;
- только вертикальный scroll;
- horizontal overflow запрещён.

## Human Playtest Gate C
Skirmish не закрывается и Battle не начинается, пока пользователь не проверит preview:
1. выбор/снятие здоровых именных фигур;
2. обязательный King;
3. лимиты 16 фигур / 39 очков;
4. видимые, но disabled wounded/dead;
5. прямой старт в реальную нестандартную шахматную позицию;
6. adaptive enemy + Stockfish;
7. сохранение wounded после взятия;
8. мат игроку → King dead → run over;
9. aftermath;
10. desktop/mobile layout;
11. главный вопрос Gate C — интересна ли сама идея собирать и рисковать своим персонализированным шахматным отрядом.
