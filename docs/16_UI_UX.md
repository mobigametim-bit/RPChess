# 16 — UI / UX

## Визуальный контракт
Сохраняем текущий approved RPChess UI-дизайн и существующие подходящие ассеты.

Главное меню и повторно используемые системные экраны должны визуально наследовать production-ready композицию предыдущей RPChess. Из них убираются только элементы систем, которых ещё нет в Reboot; вместо этого не создаётся отдельный «прототипный» визуальный язык.

## Глобальный framed-content safe-area contract
Это обязательное правило **для всей игры, всех текущих и будущих сцен**.

Любая декоративная UI-рамка, внутри которой находится текст или интерактивные элементы, обязана иметь внутреннюю safe-area:
- текст, заголовки, формы, кнопки и другие интерактивные элементы располагаются только внутри визуальной внутренней области рамки;
- контент не должен касаться декоративной кромки или визуально заходить на неё;
- слева всегда используется дополнительный внутренний отступ, немного больше правого, чтобы текст не стоял вплотную к рамке;
- длинный текст обязан переноситься внутри safe-area, а не расширять или пересекать рамку;
- правило одинаково обязательно для модальных окон, боковых панелей, карточек, экранов выбора, настроек, результатов и любых новых framed surfaces;
- новые framed surfaces должны использовать общий `.ui-frame-safe` / `--ui-frame-safe-*` контракт, а не задавать произвольные локальные отступы;
- на mobile safe-area может быть компактнее, но не исчезает.

Текущие системные семейства `.reboot-modal__panel` и `.classic-panel` подключены к этому контракту централизованно в `reboot-foundation.css`, поэтому будущие изменения их decorative frame не должны требовать ручной корректировки каждого экрана.

## Общие правила
- любая страница должна вертикально скроллиться, если не помещается во viewport;
- UI по умолчанию показывается как production-ready интерфейс, без developer notes, статусов реализации и длинных пояснений внутри игрового экрана;
- пояснение допустимо локально там, где уже существует кнопка/элемент, а сама функция ещё не реализована;
- существующие approved panel/button/background/wordmark assets переиспользуются, пока не принято отдельное решение об их замене;
- музыка и UI SFX должны быть реально подключены на экранах, где присутствуют соответствующие настройки и готовые аудио-ассеты;
- шахматная доска остаётся главным интерактивным объектом боя;
- кликабельная область фигуры должна соответствовать её видимому силуэту;
- selected state обозначается ясной рамкой/подсветкой, без лишних checkbox, если весь элемент кликабелен;
- desktop и mobile проходят browser acceptance.

## Workflow
UI-feature считается принятой только после живого playtest пользователя, даже если Chromium CI зелёный.
