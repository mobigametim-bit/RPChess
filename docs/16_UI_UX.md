# 16 — UI / UX

## Визуальный контракт
Сохраняем текущий approved RPChess UI-дизайн и существующие подходящие ассеты, но декоративный ornate panel-frame asset больше не является частью production UI.

Главное меню и повторно используемые системные экраны должны визуально наследовать production-ready композицию RPChess. Из них убираются только элементы систем, которых ещё нет в Reboot; вместо этого не создаётся отдельный «прототипный» визуальный язык.

## Глобальный frameless panel contract
Это обязательное правило **для всей игры, всех текущих и будущих сцен**.

Декоративные panel-frame assets `ui_panel_frame.png` и `ui_panel_wide.png` запрещено использовать в активном production UI.

Все панели, модальные окна, карточки и системные surfaces строятся CSS-only:
- тёмная внутренняя подложка;
- тонкая синяя или сдержанная золотистая обводка;
- мягкая тень/свечение без тяжёлой декоративной рамки;
- контент размещается только внутри собственной safe-area;
- текст, заголовки, формы и кнопки не должны касаться внешней границы surface;
- слева используется дополнительный внутренний отступ, немного больше правого, чтобы текст не стоял вплотную к краю;
- длинный текст переносится внутри safe-area и не расширяет surface;
- на mobile safe-area может быть компактнее, но не исчезает;
- будущие surfaces используют общий `.ui-panel-safe` / `--ui-panel-safe-*` контракт и глобальные `--ui-panel-*` visual tokens, а не локальные произвольные рамки.

Текущие `.reboot-modal__panel`, `.classic-panel`, Roster detail/catalog и внешняя обкладка шахматной доски приведены к frameless CSS-only treatment.

## Глобальный button contract
Все обычные CTA/action controls в production UI должны быть **CSS-only** и визуально наследовать утверждённый obsidian/gold язык главного меню и Settings:
- тёмный obsidian/gold gradient;
- тонкая золотая внешняя граница;
- угловая геометрия без image-frame;
- сдержанный внутренний stroke;
- золотой hover/focus treatment;
- BrahmsGotischCyr для основных action labels, если конкретная сцена не задаёт более специальный typography contract.

`ui_button_primary.png` и другие image-border CTA assets не являются частью текущего каноничного production button contract. Они могут оставаться в репозитории только как legacy/unused assets и не должны возвращаться в активные `.reboot-button` / `.reboot-close` rules.

Специализированные selection controls — карточки маршрутов/событий, Roster cards/filters, выбор бойцов, клетки доски и аналогичные purpose-built элементы — не обязаны выглядеть как primary CTA, если их отдельный interaction language уже утверждён.

## Общие правила
- любая страница должна вертикально скроллиться, если не помещается во viewport;
- UI по умолчанию показывается как production-ready интерфейс, без developer notes, статусов реализации и длинных пояснений внутри игрового экрана;
- пояснение допустимо локально там, где уже существует кнопка/элемент, а сама функция ещё не реализована;
- музыка и UI SFX должны быть реально подключены на экранах, где присутствуют соответствующие настройки и готовые аудио-ассеты;
- шахматная доска остаётся главным интерактивным объектом боя;
- кликабельная область фигуры должна соответствовать её видимому силуэту;
- selected state обозначается ясной CSS-подсветкой/обводкой, без лишних checkbox, если весь элемент кликабелен;
- desktop и mobile проходят browser acceptance.

## Запрет на возврат ornate frames
Новая feature не может добавлять ссылки на `ui_panel_frame.png` или `ui_panel_wide.png` в active Reboot CSS/HTML. Static verification должен считать такую ссылку регрессией.

Legacy-ветка может хранить старое использование этих файлов как исторический срез; это не является разрешением для нового production runtime.

## Workflow
UI-feature считается принятой только после живого playtest пользователя, даже если Chromium CI зелёный.
