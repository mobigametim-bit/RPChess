# 04 — Roster

## Назначение
Roster — постоянный экран текущего забега, где игрок видит **своих персонализированных шахматных персонажей**, их классическую шахматную роль и текущее состояние.

Это **не** экран формирования армии для Стычки. На Roster нет checkbox, `Применить состав`, лимитов `16/16` или `39/39`, стартовых клеток, drag-and-drop и кнопки `В бой`.

## UX
Desktop:
- слева — крупная карточка выбранного персонажа;
- справа — каталог карточек всего отряда;
- вся карточка персонажа кликабельна;
- selected-state передаётся CSS-подсветкой и `aria-pressed`;
- используются реальные legacy portrait / piece assets из сохранённой предыдущей версии RPChess;
- detail/catalog и все системные surfaces используют game-wide frameless `.ui-panel-safe` / `--ui-panel-*` contract;
- ornate assets `ui_panel_frame.png` и `ui_panel_wide.png` запрещены;
- action-кнопки используют approved синий `ui_button_primary.png`;
- `Начать путешествие` — главный forward CTA текущей версии Roster.

Mobile:
- detail выбранного персонажа идёт первым;
- затем фильтры и карточки;
- экран естественно прокручивается вертикально;
- горизонтальный overflow не допускается;
- safe-area остаётся обязательной и на узком viewport;
- `Начать путешествие` остаётся доступной в верхнем action block.

## Стартовый отряд
Новая игра автоматически создаёт один постоянный run с шестью персонализированными фигурами:

| Персонаж | Роль | Классическая стоимость |
|---|---|---:|
| Хранитель Клятвы | Король | 0 |
| Альдрик Стена | Ладья | 5 |
| Мара Цепь | Пешка | 1 |
| Немея Перо | Пешка | 1 |
| Брат Орелл | Слон | 3 |
| Ваэль Молот | Конь | 3 |

Итого: **13 командных очков + обязательный Король**. Ферзь намеренно не выдаётся на старте и должен стать ценной будущей находкой/наёмником.

## Король
- выбор Короля отдельной страницей не используется;
- новый run автоматически получает персонализированного `Хранителя Клятвы`;
- он отмечается как `КОРОЛЬ ОТРЯДА`;
- стоит 0 командных очков;
- он обязателен в Skirmish/Battle;
- смерть Короля завершает run;
- в detail используется такая же character-history подача, как у остальных именных фигур, без механического пояснения о завершении run.

Текущая мини-история Хранителя Клятвы: последний хранитель древней присяги Железных Маршей, покинувший родовую крепость после её падения и собравший вокруг себя тех, кто ещё верит, что данное слово важнее трона.

## Классическая стоимость фигур
Roster обучает игрока классической материальной стоимости:
- Пешка — 1;
- Конь — 3;
- Слон — 3;
- Ладья — 5;
- Ферзь — 9;
- Король — 0.

Общий лимит `39` здесь **не показывается**. Он относится к формированию армии для Skirmish и к стандартному Battle army contract.

## Статусы
В runtime используются:
- `healthy` → `ЗДОРОВ`;
- `wounded` → `ТЯЖЕЛО РАНЕН`;
- `dead` → `ПОГИБ`.

Для `healthy` дополнительная служебная фраза под статусом не выводится.

`ТЯЖЕЛО РАНЕН` остаётся доступен для просмотра, но не может участвовать в бою до будущего лечения.

`ПОГИБ` не удаляется из истории забега. Карточка остаётся в фильтре `ПОГИБШИЕ` как мемориал текущего run, но персонаж больше не считается живым roster и не может вернуться в бой.

## Фильтры первой версии
Только четыре состояния:
- `ВСЕ`;
- `ЗДОРОВЫ`;
- `РАНЕНЫ`;
- `ПОГИБШИЕ`.

Фильтры по роли пока не нужны.

## Persistence
Run хранится локально под reboot namespace. Roster-связанные поля включают:
- `schemaVersion`;
- `id`;
- `createdAt` / `updatedAt`;
- `selectedCharacterId`;
- массив `roster` со статусами персонажей.

Общая run schema также содержит данные Skirmish/Battle/Travel Choice и гидратирует старые saves обратно совместимо.

После `Новая игра` run сохраняется сразу. Кнопка `Продолжить` становится активной и после перезагрузки возвращает игрока на экран `Отряд` с тем же выбранным персонажем и статусами.

## Forward flow текущего preview
Roster не является тупиковой сценой.

Кнопка `Начать путешествие` открывает **Travel Choice** — отдельную сцену с тремя следующими путями. До выбора encounter игрок может открыть `Отряд` и затем снова нажать `Начать путешествие`: сохранённая тройка не перегенерируется.

Если путь уже выбран и encounter ещё не завершён, возврат в Roster не позволяет заменить решение: `Начать путешествие` возобновляет уже выбранный encounter.

Текущий flow:

`Отряд → Начать путешествие → 3 Travel Choice cards → Skirmish/Battle → aftermath → Продолжить путь`.

## Граница с другими feature
- `Skirmish` формирует боевой состав до 16 фигур / 39 очков;
- `Battle` использует полный стандартный комплект и временные generic фигуры;
- `Travel Choice` отвечает за выбор следующего encounter и persistence развилки;
- `Settlement` позже изменит `wounded → healthy` через лечение и добавит найм;
- Resources/Starvation позже добавят стоимость перехода и последствия нехватки Supplies.

## Реализация
Feature branch исходной Roster feature: `feature/roster`; текущий accepted Roster уже merged в `main`.

Основные модули:
- `game/js/roster-data.mjs` — персонажи, роли, стоимость, стартовый набор и character copy;
- `game/js/run-persistence.mjs` — schema v1 и localStorage persistence;
- `game/js/roster-app.mjs` — scene routing, detail/card/filter UI, Continue и Start Journey routing;
- `game/css/roster.css` — production Roster layout;
- `tests/roster.cjs` + `tests/roster-browser.cjs` — deterministic и real-Chromium acceptance.

## Human Acceptance
Roster закрыт как **IMPLEMENTED → AUTOTESTED → DEPLOYED → HUMAN ACCEPTED → DONE**. Последующие Travel Choice изменения не меняют утверждённую модель Roster, а заменяют только прежний временный forward bridge каноническим путешествием.
