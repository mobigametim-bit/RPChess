## Player Identity

После нажатия `Новая игра` новый run больше не создаётся мгновенно. Сначала поверх главного меню открывается центральный frameless prompt:

- eyebrow `НОВЫЙ ПОХОД`;
- заголовок `КТО ТЫ, ВОИН?`;
- обязательное поле имени;
- `ПРОДОЛЖИТЬ`.

Имя нормализуется: пробелы по краям удаляются, повторные пробелы схлопываются, максимальная длина — 24 символа. Пустое имя не позволяет продолжить. Закрытие prompt не создаёт новый run и не уничтожает существующее сохранение.

После подтверждения создаётся обычный run и продолжается существующая последовательность сцен. `playerName` является частью persistent run-state и переживает reload. Старые сохранения без поля `playerName` мигрируют с безопасным fallback `Воин`, чтобы не ломать существующий persistence contract.

Кнопка `НОВАЯ ИГРА` на итоговом экране Endless Run также сначала открывает тот же prompt, поэтому каждый новый поход может получить новое имя.

## Имя игрока в Events

Имя используется только там, где `Король` в литературном Event-тексте обозначает личность/героя игрока.

Глобальный blind string replace запрещён. Подстановка выполняется на presentation-слое при рендере всех текущих 500 событий и сохраняет грамматику там, где это возможно без склонения произвольного имени:

- именительный `Король` → имя игрока;
- безопасные косвенные конструкции могут переходить во второе лицо: `к Королю` → `к вам`, `говорит Королю` → `говорит вам`, `Короля встречают` → `вас встречают`;
- заголовки/сюжет/реакции и подписи решений могут персонализироваться;
- исходные authored event-data не мутируют.

Системные и шахматные значения остаются `Король / King`: тип фигуры, шах/мат, технические статусы, warning `КОРОЛЬ МОЖЕТ ПОГИБНУТЬ` и аналогичные gameplay-сообщения не переименовываются.

## Chronicle / Летопись

На стартовом экране справа от основного блока кнопок расположен отдельный атмосферный frameless-блок `ЛЕТОПИСЬ`. На узких экранах он перестраивается под меню вертикально без horizontal overflow.

### Текущий поход

Если есть активный run, показываются:

- Имя;
- Мощь;
- Неделя;
- Героев в строю — все `healthy + wounded`, без `dead`.

Gold и Supplies в Летопись не входят: это не economy HUD, а профильная/историческая поверхность.

Если активного run нет, показывается нейтральное состояние `Нет активного похода`.

### Лучший поход

Для завершённых походов показываются:

- Имя;
- Слава;
- Неделя;
- Мощь.

**Причина окончания похода в Летописи не хранится и не показывается.**

Если завершённых походов ещё нет: `ЛУЧШАЯ ЛЕТОПИСЬ / Летопись пуста / Ни одно имя ещё не вписано в её страницы.`

## Слава похода

Формула утверждена пользователем:

`Слава = floor(sqrt(Неделя × Мощь) / 10)`

Пример: неделя 35, Мощь 900 → `sqrt(31500) / 10 ≈ 17.748` → **Слава 17**.

Лучший поход выбирается по:

1. максимальной Славе;
2. при равной Славе — большей Неделе;
3. затем — большей Мощи.

## Persistence

Летопись хранится отдельно от active run в profile-like key `rpchess.reboot.v1.chronicle`. Это позволяет `Новой игре` заменять run-state, не стирая историю предыдущих походов.

Текущий локальный history limit — 20 завершённых походов. Запись idempotent по `runId`: reload итогового экрана не создаёт дубликаты. Если финальный Power данного run был досчитан после первого record, запись того же `runId` может обновиться вместо создания дубля.

В запись завершённого похода входят только данные, нужные Летописи и будущему рейтингу: `runId`, `playerName`, `week`, `power`, `glory`, timestamp завершения. `endReason` намеренно отсутствует.

Архитектура должна позволять позже заменить/расширить локальный best block на multiplayer leaderboard: top players + собственная позиция игрока, не переделывая основную компоновку главного меню.
