# B10 — аудит экономики и сервисных контрактов

Дата: 7 августа 2026.

## Расхождения legacy runtime

До B10 Stage B использовал несколько правил, конфликтующих с решениями №51–61:

| Контракт | Legacy | B10 production |
| --- | --- | --- |
| Стартовые припасы | зависели от прежнего campaign bootstrap и бонусов | ровно 10, если контент явно не разрешает иное |
| Стартовое золото | runtime начинал с 0 | 80 + explicitStartModifiers |
| Обычная награда | могла содержать адаптивные/малые значения | три предложения: сила, 3 припаса, 30/50/70 золота |
| Адаптация наград | зависимость от runtime context | запрещена |
| Магазин | старый специализированный набор | 4 сохранённых позиции: ресурс / реликвия / фигура-усиление / редкий региональный товар |
| Госпиталь | старые динамические предложения | 25 / 50 / 60 / 90 |
| Кузница | общий service path | только реликвии; 50 / 80 / 30 / 60 |
| Лагерь | отсутствовал единый production contract | ровно одно бесплатное действие |
| История экономики | агрегаты без полного transaction ledger | append-only ledger |
| Межактовые припасы | legacy carry cap/compensation | все остатки конвертируются 1:5, затем 10 припасов |

Legacy функции сохранены для старых characterization tests и старых схем. Production browser host Железных Маршей устанавливает B10 contract через отдельный adapter, чтобы не менять уже сохранённые legacy replay задним числом.

## Production constants

- `START_SUPPLIES = 10`
- `START_GOLD = 80`
- `GOLD_REWARD_VALUES = [30, 50, 70]`
- `SUPPLY_REWARD = 3`
- конвертация между актами: `1 supply = 5 gold`
- price bands: 20–30 / 40–60 / 70–100 / 110–140
- госпиталь: 25 / 50 / 60 / 90
- кузница: 50 / 80 / 30 / 60

## Миграция

Production runtime не регенерирует сохранённые награды, магазин или перековку. Отсутствующие поля B10 достраиваются при загрузке через `productionizeStageB`, а существующие значения ресурсов и материализованного контента сохраняются. Новые экономические действия записываются в ledger и сохраняются существующим atomic profile store после каждой browser-команды.

## Статистическая проверка

`tests/b10-economy-statistics.cjs` прогоняет более 10 000 актов по стратегиям `balanced`, `power`, `gold`, `supplies`, `save`, `scout`, `secret`, фиксирует стоимость маршрута, пополнение припасов, доход/расход золота, форсированные марши, покупки и тайные посещения. Для balanced-профиля проверяются целевые диапазоны Roadmap, для всех стратегий — отсутствие экономического soft-lock.
