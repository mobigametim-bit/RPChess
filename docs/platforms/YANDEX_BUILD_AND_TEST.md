# Яндекс Игры: сборка и проверка

Ветка: `feature/yandex-games`. Изменения не объединяются с `main`.
Команда `build:yandex` создаёт отдельные `dist-yandex` и `heroes-checkmate-yandex.zip`.
Обычные `build` / `build:vk` сохраняют прежнее поведение. Флаг Яндекса
внедряется только в HTML отдельной сборки.

## Сборка

```sh
npm ci
npm run verify
npm test
npm run test:yandex
npm run build:yandex
```

При сборке Stockfish скачивается из официального релиза; целостность JS,
WASM и лицензии проверяется существующими фиксированными хешами.
Можно использовать предварительно скачанные неизменённые файлы через
`RPCHESS_STOCKFISH_ASSET_DIR` — это не отключает проверку.

Архив содержит `index.html` в корне, локальные ресурсы, Stockfish и лицензии.
Упаковка проверяет распакованный размер строго меньше 100 000 000 байт
и пути без кириллицы/пробелов. Для экономии размера фоны событий
подготовлены в 1280×720, портреты — до 512×512 с сохранением прозрачности.
Музыка `epic_music3.mp3` исключена согласно пометке CC BY-NC в `CREDITS.md`;
остаются три разрешённых трека. Исходные изображения и обычный dist не меняются.
`BUILD_INFO.json` содержит платформу, дату, версию и SHA исходников.

## Автоматизация в GitHub

Workflow `Build Yandex Games ZIP` запускается при push в эту ветку и
проверяет исходники, правила игры, транспорт облака и Яндекс-сборку в Chromium.
Результат — downloadable artifact `heroes-checkmate-yandex-<SHA>` с ZIP внутри.
Публикация на VK, Pages и Яндекс не выполняется.

Если `Run workflow` пока не виден для нового файла вне default branch,
повторить существующий запуск через `Re-run jobs` либо отправить новый коммит
в рабочую ветку. Не переносить workflow в `main` ради появления кнопки.

## Браузерные проверки

```sh
npm install --no-save --package-lock=false --ignore-scripts playwright@1.54.2
npx playwright install chromium
node tests/yandex-browser.cjs
RPCHESS_BUILD_TARGET=yandex RPCHESS_GATE_PORT=4175 RPCHESS_GATE_PREFIX=/RPChess \
NODE_OPTIONS='--require=./tests/yandex-regression-preload.cjs' \
RPCHESS_BROWSER_TEST=classic-chess-browser.cjs,arena-browser.cjs,piercing-vision-browser.cjs,fork-master-browser.cjs,combat-resume-browser.cjs,caravan-browser.cjs \
npm run test:browser
```

SDK подменяется тестовой реализацией `/sdk.js`; игровая логика, ресурсы
и Stockfish настоящие. Проверяются Game Ready, выбор языка портала и ручной
выбор после reload, SDK pause/resume, остановка ходов и аудио, реклама,
отсутствие внешних игровых ресурсов, 1280×720 и 844×390/touch.
Отдельные браузерные контексты проверяют облачное продолжение на новом
устройстве, включая «Рентген» и «Мастер вилок».

Для прогона обычного dist не задавать `RPCHESS_BUILD_TARGET` и preload.

## Сохранения

Игровая схема и идентификаторы артефактов не изменены. Полная запись передаётся
одним ключом `rpchess_v1` через `getData` / `setData(..., true)`; существующее
сравнение свежести и слияние Арены остаются общими с VK. Перед записью
загружается облако; локальная копия сохраняется при сетевой ошибке.

Когда браузер поддерживает `CompressionStream` / `DecompressionStream`,
используется gzip/base64. При превышении 195 000 байт запись отклоняется без
обрезания данных и без замены прежнего облака. На старом браузере без
декомпрессии сжатая запись не перезаписывается; такой браузер не считать
подтверждённым до отдельной приёмки. В тесте 5000 записей журнала передаются
без потерь; это не гарантирует неограниченный объём будущего прогресса.

Автосохранение на Яндексе ограничено одним запланированным запуском в 5 секунд;
выход/пауза вызывает дополнительную синхронизацию. Язык и громкость остаются
настройками конкретного браузера. VK и Яндекс используют разные аккаунты
и облака; переноса существующего прогресса VK в Яндекс нет.

## Следующий шаг владельца

1. В https://games.yandex.ru/console/ создать черновик игры.
2. Загрузить `heroes-checkmate-yandex.zip` как исходный архив.
3. Открыть тестовый запуск с debug-панелью и передать ID/ссылку на черновик.
4. Проверить настоящий SDK: Game Ready, язык RU/EN, rewarded (успех/закрытие),
   паузу при рекламе и смене вкладки, продолжение боя, облако на втором устройстве,
   гостя и авторизованного игрока, переход между ними, Stockfish/WASM.

До этой проверки не отправлять игру на модерацию и не отмечать платформенную
приёмку завершённой. Договор, карточка, промоматериалы, устройства и возрастной
рейтинг остаются этапами согласованного плана. iOS и конкретные Android-устройства
ещё не подтверждены локальной эмуляцией Chromium.
