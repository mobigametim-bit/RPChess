При необходимости нового продуктового решения или действия владельца остановиться и сообщить ему. Не менять баланс или игровые механики ради портирования.

«Рентген» и «Мастер вилок» уже находятся в исходной версии и должны войти в сборку.

## Пошаговый план
1. Создать ветку от актуального main. Добавить отдельную команду build:yandex, каталог dist-yandex, архив heroes-checkmate-yandex.zip, информацию о версии и исходном коммите.
2. Аккаунт разработчика: зарегистрирован. Владелец оформляет договор и создаёт один черновик игры в https://games.yandex.ru/console/. Проверить эти действия перед модерацией.
3. Измерить полный размер распакованного dist и подготовить архив меньше 100 МБ; целевой бюджет 90 МБ. Сжатие ZIP не снижает размер распакованного содержимого. Оптимизировать ресурсы без удаления игрового контента. index.html в корне, пути без кириллицы и пробелов.
4. Сделать ресурсы автономными: заменить абсолютные ссылки на GitHub Pages локальными, включить музыку, SFX, иконки, изображения, Stockfish и необходимые лицензии. Исключить музыкальный трек, отмеченный в CREDITS.md как не разрешённый для коммерческого выпуска, либо заменить после решения владельца.
5. Добавить адаптер Yandex в platform.mjs. Подключить /sdk.js и YaGames.init(). Вызвать LoadingAPI.ready() после готовности ресурсов, сохранений и интерактивного меню. Разметить GameplayAPI.start()/stop() по фактическому состоянию игры.
6. При первом запуске определить язык через ysdk.environment.i18n.lang. Поддержать RU/EN и сохранённый ручной выбор. Проверить название, все экраны и описания артефактов. Адаптировать «Поделиться», чтобы версия Яндекса не ссылалась на игру VK.
7. Подключить player.getData()/setData() при сохранении существующей игровой схемы. Лимит данных 200 КБ; не переносить VK chunk transport буквально. Локальная резервная копия, загрузка облака до записи, выбор более свежего состояния. Проверить гостя, авторизованного пользователя и переход между ними без потери данных.
8. Подключить rewarded-рекламу к существующим предложениям наград. Начисление только по onRewarded, защита от повторной выдачи. Fullscreen-реклама в подходящих перерывах. Постоянный sticky-баннер отключён для первого выпуска. Пауза игрового процесса и аудио при рекламе, потере фокуса и событиях SDK; корректное восстановление с учётом уже открытого меню/паузы.
9. Провести автоматические и браузерные проверки: Journey/Battle/Skirmish/Caravan/Arena, оба артефакта, шахматный бот, покупки, расход, награды, продолжение боя, старые сохранения, RU/EN, desktop/mobile landscape, rotate screen, touch, отсутствие контекстного меню. Добавить ручной GitHub Actions workflow сборки с контролем размера/путей/корня и выдачей ZIP.
10. Подготовить карточку RU/EN: название, SEO, короткое описание, «Об игре», «Как играть». Промоматериалы: PNG-иконка 512×512, PNG-обложка 800×470; не менее 2 реальных скриншотов на каждую заявленную платформу (landscape 16:9, длинная сторона 1280–2560, JPEG/24bit PNG); видео MP4 16:9, до 28 секунд, высота от 400 px, до 100 МБ. Отдельная композиция обложки с героями и шахматной тематикой. Новую генерацию согласовать, если она потребуется.
11. Владелец загружает ZIP в черновик; выставляет только проверенные устройства, альбомную ориентацию, RU/EN, жанры и возрастной рейтинг по содержанию. Отметка облачных сохранений после фактической интеграции SDK. Проверить внутри Яндекса через debug-панель: SDK, Game Ready, язык, реклама, облако, паузы, файлы, bot/WASM. Локальный mock не заменяет платформенную приёмку.
12. Включить отсроченную публикацию, отправить на модерацию после оформления договора. Обычно проверка занимает 3–5 рабочих дней. Исправить замечания в ветке и загрузить новый ZIP. После одобрения владелец публикует игру.
13. Обновлять ту же карточку игры и её ID: переносить нужные изменения из main в feature/yandex-games, повторять проверки, собирать новый ZIP. Слияние адаптации в main не требуется.

## Известные зависимости и ограничения
- После оптимизации: 75 461 757 байт распакованных файлов; ZIP 68 102 378 байт. Лимит 100 МБ выдержан.
- Облачные данные Яндекса ограничены 200 КБ; проверять длительное путешествие и летопись.
- GitHub workflow_dispatch может потребовать первоначального появления нового workflow в default branch; не менять main ради этого без обсуждения. Возможен запуск push-workflow только на рабочей ветке.
- Для проверки на площадке необходим черновик и его ID/URL от владельца.
- Реальные рекламные callbacks и облако принимаются в среде Яндекса.
- Локальные проверки не дают статуса «готово к публикации» до платформенной приёмки.
